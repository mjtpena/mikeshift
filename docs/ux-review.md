# MikeShift UI/UX review (U1)

Reviewer: U1. Build reviewed: branch `feature/windows-port` @ `6c211db`, Debug x64, Windows 11 26300, dark system theme, 100 % primary display. Screenshots are in `docs/screenshots/ux/` (own capture harness; backdrops are synthetic, nothing from the user's desktop). Names in the code are still "Shiftvert"; branding is out of scope except in the last section.

## How this was done

* Click-mode wheel driven live (`--convert`) for image, video, document, PDF, audio, mixed and unknown files: dark, light, `hc` (emulated), DPI 1.5 and 2.0, animations off. UI Automation trees dumped for the wheel, Crop, Trim, Settings, Welcome and the tray menu.
* Toast, partial-failure and all-failed dialogs triggered by real jobs invoked through UIA on the wheel tiles; "in Downloads" produced with a write-denied scratch folder (the one output written to Downloads was deleted afterwards).
* Crop, Trim, Settings, Welcome opened with the dev flags; tray menu popped by launching a second instance.
* **Not exercised** (no input injection allowed): real Shift-drag with Explorer's drag thumbnail (findings W-01, W-02, W-03 rest on the existing screenshots, the code and the reported behaviour), OS-level high contrast (the `hc` env var only re-uses the current colours), light theme for the XAML windows (needs the OS theme switched), Narrator, 150 %/200 % for XAML windows, the Convert Files dialog's content (it listed the user's private Documents folder, so the screenshot was deleted).
* Measured contrast (sampled from `wheel-formats-dark.png` etc.): hub hint 3.98:1 dark / 4.22:1 light; white label on the default accent tile 4.03:1 (top of gradient) / 5.9:1 (bottom); tool-tile caption on dark glass 7.0:1.

## Summary

1. The core idea and the wheel's geometry transfer well, and the editors are functional and accessible (named controls, key help text, Enter/Esc). The wheel feels like a Mac port rather than something Windows shipped: 8.5-12 px text, uppercase tracked labels, bare-text format tiles, muddy glass.
2. The **supporting surfaces are not Windows 11 yet**: a classic light Win32 tray menu and MessageBox failure dialogs in a dark OS, light title bars over dark content on every XAML window, and a Settings page that is a plain stacked form.
3. The **toast is broken in small, visible ways**: the text is clipped ("photo 4.p…", "in Downlo…"), descenders are cut, the first toast of a session shows a black box for ~0.4 s, and the window edge shows a white hairline with black corner slivers. It also cannot tell the user where the file went or open it.
4. **First-run and error copy** is the weakest part of the product experience: a wall of text with no picture of the wheel, "skipped" meaning "failed", errors that do not name the file.
5. Everything is fixable inside the current architecture (Win2D wheel, WinUI 3 windows); the P0/P1 items are mostly sizing, theming and copy.

No P0 (nothing blocks use). 

## Findings

Severity: P0 blocks use, P1 clearly wrong, P2 polish, P3 nice to have. Evidence files are in `docs/screenshots/ux/` unless noted.

## Branding hooks (where "MikeShift" and the icon must appear)

* **Tray**: icon (16/20/24/32 px set + HC variant), tooltip, menu header, "Exit", About line.
* **Wheel**: the hub is the natural place for a small mark; recommend the wordmark/icon at 10 % opacity only in the idle hub of the first 5 wheels, never over tile text. The margin pill (W-01/W-04) must not carry the name.
* **Windows' title bars and Alt+Tab/taskbar**: every window title ("MikeShift settings" is wrong, use "Settings"; Crop/Trim titles "Crop - photo.jpg" keep the file name), `AppWindow.SetIcon` in `EditorWindows.Setup`, Settings, Welcome, the toast (`Title`), the action picker.
* **Dialogs**: title row icon and the product name in body text only where needed (e.g. "MikeShift is running as administrator").
* **Welcome**: hero icon 64 px, title "Welcome to MikeShift", the first line of intro.
* **Settings**: About card (icon 48 px, name, version, "Check for updates", "View on GitHub", log folder, licence/NOTICE link to the upstream Shiftvert credit).
* **Package**: `Package.appxmanifest` `DisplayName`, `Description`, `PublisherDisplayName`, the 44×44, 150×150, Store logo, `StartupTask DisplayName` (this is the name shown in Settings > Apps > Startup), `uap:VisualElements` for the CLI ("MikeShift command line"), `Identity Name`/`Publisher` and `make-dev-cert.ps1` subject; `shiftvert.exe` execution alias (keep a `mikeshift.exe` alias, optionally keep the old one).
* **Installer/first launch**: Start menu entry name, the single-instance key `shiftvert`, log folder `%LOCALAPPDATA%\Shiftvert`, settings.json folder (migrate on first run), `ReleasesUrl`.
* **Copy**: every literal "Shiftvert" in `WelcomeWindow.xaml`, `SettingsWindow.xaml(.cs)`, `TrayController`, `FeedbackPlan` (dialog title), `CodecSummary.StoreHint`, `App.xaml.cs` (elevation dialog), `ToastWindow.xaml` title, README/NOTICE (keep the credit to roiegold/Shiftvert).
* **Upstream credit** belongs in Settings > About and NOTICE, not in dialogs.
