# Real-drag verification (G2), 2026-10-24

Every drag below started from a **real File Explorer window** (or, for the non-file cases, a real Notepad window and a real window title bar) on a file in a temp folder under `%TEMP%\mikeshift-g2\`, driven with `SendInput` by `tools/DragHarness` (`--anger`). Nothing was dragged out of the harness's own window.

* Build: `feature/windows-port` @ `94b8312` plus the harness changes in this commit (no product code changed). Debug x64, Windows 11 26300, dark theme, 100 % scaling on both monitors.
* Machine: `\\.\DISPLAY5` 3440 x 1440 primary at (0,0) with a 48 px bottom taskbar (work area 3440 x 1392); second monitor 1920 x 1080 at (-1920,0), **no taskbar on it** (work area equals bounds), so "taskbar on the second monitor" does not apply here.
* Run: `MIKESHIFT_ANGER_ROOT=%TEMP%\mikeshift-g2 DragHarness.exe --anger <scenarios> --app <MikeShift.exe>`. The app runs with `MIKESHIFT_ACCEPT_INJECTED=1` and `MIKESHIFT_TRACE=1`; log lines quoted below come from its trace log.
* Result: **all product checks pass except one (Open, below)**. 32 scenarios, more than 400 checks (the first run of 20 scenarios: 285 checks passed, none failed).
* Screenshots (`docs/screenshots/real-drag/`) are BitBlt captures of the screen cropped to the wheel; crops were chosen so that no window of the user's is visible.

## 8. Latency and idle cost

Scenarios `x8-primary`, `x8-left` (new): 21 Shift-drags each (first = cold after app start, then 20 warm) from a real Explorer on that monitor, each aborted with Esc. Latency is the time from the harness's `SendInput` Shift down to the app's log line `wheel shown pending` (same clock).

| Monitor | cold (first drag) | 20 warm drags, log timestamps | window visible per 2 ms polling |
|---|---|---|---|
| Primary | 31 ms | min 16, median 22, p95 28, max 28 ms | 45 to 47 ms* |
| Second (-1920,0) | 29 ms | min 13, median 24, p95 28, max 28 ms | 44 to 47 ms* |

\* the polled figure includes the harness's own 40 ms key-settle sleep, so it is about 5 ms later than the Shift press + 40 ms; the log figure is the honest one. The PLAN target is under 100 ms: **Pass** on both. In the ordinary scenarios the polled figure was 44 to 78 ms (the 78 ms one a bottom-left corner drag with the CPU busy).

Idle (primary run, after the drags and then 120 s without touching the app, sampled over the next 30 s): working set **16.5 MB**, private working set **6.5 MB**, CPU **0.00 %** of one core, 24 threads, 1004 handles. **Pass** (target under 100 MB; LIMITS says about 17 MB).

## Fixed, open and harness changes

| ID | State | Detail |
|---|---|---|
| O-1 | **Open, P2** | The tray flyout opened by a right click does not react to the keyboard: the foreground window is the app's own flyout-host window (pid matches), yet Down arrow highlights nothing and Esc leaves the menu open; it closes only on a click elsewhere or on the tray icon. Keyboard users cannot drive the tray menu. I tried focusing the first item in `Opened` (`TrayFlyoutHost`), which changed nothing, and reverted it. The harness check `x5f: Esc closed the flyout` therefore keeps failing until this is fixed. Probable cause: the flyout is a separate popup window and the XAML island that owns keyboard focus is the 2 x 2 px transparent host window; focus would have to be given to the popup's content (or the flyout shown with `FlyoutShowMode.Standard`). |
| O-2 | Open, P3 | `MIKESHIFT_PICKER_FOLDER` with forward slashes (`C:\x/y`) throws `ArgumentException` in `ItemFor` (logged as `[ERROR] picker start folder`; the dialog then opens in Pictures). Dev-only knob; `Path.GetFullPath` on the value would fix it. |
| H-1 | Harness fixed | The tray icon's UI Automation name is now "MikeShift - Shift-drag files to convert" (it was "MikeShift"): `FindIcon` matches the prefix. |
| H-2 | Harness fixed | The picker is owned by the app's invisible helper window, so UI Automation lists the dialog under that owner, not under the desktop: `AppDialog` uses `EnumWindows`. Its button is "Choose" (it was "Open"). |
| H-3 | Harness fixed | Left click is now Convert files... directly (there is no menu step); `x5a` to `x5e` follow the new flow and pass again. |
| H-4 | Harness added | `x1j` (Compress, Resize 50% from Explorer), `xw` (pill against the real thumbnail), `x3-taskbar`, `x8-primary`/`x8-left` (latency and idle), `x5f` (right click flyout, picker, toast, Show in folder); `MIKESHIFT_ANGER_ROOT` moves the work folder; `Anger.MakeFixtures` writes the one-page PDF `x1f` needs; `Pointer.RightDown/RightUp`. |
